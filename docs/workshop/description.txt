[b]This is not a Lua mod. Subscribing downloads the files; you still install them by hand (or with the included script).[/b] Enabling it in the Mods list does nothing.

Class overrides for Project Zomboid Build @VERSION@ (game revision @REV@) that shorten chunk-streaming stalls and tighten the frame time, plus a full options tab (Options > Optimizations) and an in-game frame-time overlay (F9). Single player and multiplayer, client side only; nothing to install on a server. Works with the Steam version on Windows and Linux (both depots ship the same jar).

Source, measurements, videos and the same files as a GitHub release:

[h1]What it does[/h1]
Project Zomboid loads and bakes the map in chunks; on stock, the loading, baking and lighting work of a busy screen lands in the same frame and shows as stutter while driving or turning. These overrides move that work off the game thread, spread it over frames, and cache what stock recomputes every frame (puddles, rain, cutaways, light info, sound zones). Bench numbers on the repository page; the short version at 5120x2160 on an RTX 4090: driving p99 frame time 19 -> 8 ms, uncapped ~270 -> ~500 fps, thunderstorms 83 -> 188 fps.

[img]https://raw.githubusercontent.com/xD3I/PZ_Optimization/master/docs/workshop/images/07-results.jpg[/img]

[h1]Boot and load times[/h1]
Launch to main menu and Continue to world ready, both games started together on the same save: stock 7.55 s + 7.67 s, optimized 4.88 s + 3.47 s (the load is less than half). FMOD and the animation sets initialise on boot threads, the file pool is pumped while the logo shows, Lua is precompiled and the animation clip and pack indexes are cached under Zomboid/pzopt/, so the first boot after installing is a few seconds slower and every later one is faster than stock.
[img]https://raw.githubusercontent.com/xD3I/PZ_Optimization/master/docs/workshop/images/01-boot-load.jpg[/img]

[h1]How it works[/h1]
The launcher (ProjectZomboid64.json) searches the game folder before projectzomboid.jar, so a loose .class file with the same name as one in the jar replaces it. The item holds those files (@NFILES@ entries: @NOVERRIDES@ shadowed game classes, the pzopt helper package, three Lua files for the options tab and a manifest) under [b]pzopt-classes[/b]. projectzomboid.jar is never modified. A guard compares your game revision and the sha256 of every stock class it shadows against the jar at start-up; if anything differs (another game build) it logs one line to console.txt and the game runs as stock, so a mismatch has no effect.

[h1]Install on Windows[/h1]
1. Subscribe, let Steam download the item, close the game.
2. Open PowerShell (Start menu, type powershell) and run (adjust the drive if your Steam library is elsewhere):
[code]powershell -ExecutionPolicy Bypass -File "C:\Program Files (x86)\Steam\steamapps\workshop\content\108600\@ID@\mods\PZ_Optimization\42\install.ps1"[/code]
The script finds the game through Steam's library list, checks the revision, refuses to overwrite anything that already exists, copies the files next to the jar and records them in pzopt-installed.txt.
3. Launch the game from Steam. The first boot is a few seconds slower (caches are written under %USERPROFILE%\Zomboid\pzopt\). console.txt shows one "[pzopt] loaded override ... active" line per class.

Uninstall: the same command with -Uninstall. -Status lists what is installed and whether any file changed.

Without the script: copy the contents of the item's pzopt-classes folder into the folder that holds projectzomboid.jar (do not overwrite anything; if a file already exists you have an older install, remove it first). Removal is deleting the files listed in pzopt-files.txt.

[h1]Install on Linux[/h1]
[code]bash ~/.local/share/Steam/steamapps/workshop/content/108600/@ID@/mods/PZ_Optimization/42/install.bash[/code]
(Steam Workshop items cannot contain .sh files, hence .bash.) Same flags: --status, --uninstall, --dir <game folder>.

[h1]Performance overlay (F9)[/h1]
[img]https://raw.githubusercontent.com/xD3I/PZ_Optimization/master/docs/workshop/images/09-performance-overlay.jpg[/img]
Off by default: tick "Sample frame times and utilization" in Options > Optimizations > Performance overlay and restart the game, then F9 toggles it (without the tick box F9 only shows a notice). Presented frame time, p50 / p99 / p99.9 / max, 1 %-low, jitter and spikes over the last 5 s, GPU busy (GL timer query), game-thread and render-thread load, process and machine CPU, heap, a verdict line (GPU bound / game thread bound / at the cap) and the frame graph. Same numbers on Windows and Linux, no MangoHud or RivaTuner needed; every run also logs it to Zomboid/pzopt-overlay.out.

[h1]Settings[/h1]
Options > Optimizations in the game (saved to Zomboid/pzopt/options.ini, applied on the next launch) has every key with a tick box, plus "Disable all (stock game)" / "Enable all". Options > Display gains an "Uncapped" framerate entry and a separate menu framerate. F9 toggles the performance overlay.

[h1]Updates[/h1]
The files are built for one game revision. When the game updates, the guard turns them off (stock game, one console line) until a build for the new revision is published here; then run the installer with -Uninstall / --uninstall and again without.

[h1]Compared with the other performance mods[/h1]
The most-subscribed Build 42 performance mods on the Workshop, each run on the same three routes (a 120 km/h drive, the same drive in a thunderstorm, a spinning walk through Rosewood), uncapped, 5120x2160, one mod at a time on the stock game, measured by the in-game overlay log. Every mod was checked in the console to be loaded and patching. Numbers: fps mean / p99 frame time.
[img]https://raw.githubusercontent.com/xD3I/PZ_Optimization/master/docs/workshop/images/10-workshop-mods-comparison.jpg[/img]
Every one of them measures within run-to-run noise of the stock game (fps within 4 %, p99 within 3 ms). They differ in what they touch, not in the result:
[list]
[*][b]Project Zomboid Optimiser[/b] (23 k): Lua. Flips engine debug/performance toggles at game start (visibility, cheap occlusion, off-screen zombie animation delay, roof hiding), replaces ~40 of the game's shaders with copies, runs a per-tick Lua heartbeat, and forces texture compression on in options.ini. Its "JVM Engine" half is a separate launcher jar from GitHub (agent + native library + G1/JIT flags, a 12-worker chunk streamer, thread priorities); with it installed the numbers are the same.
[*][b]Tempo[/b] (42 k): Lua frame sampler, spike attribution and a context-menu width memo; optional class shadows for 42.20.4 (a 2.5 ms/frame chunk-finalize budget in IsoChunkMap and a 3D-zombie cap in IsoWorld). The budget spreads the finalize work but the tail while driving is the chunk queue wait, which it does not touch.
[*][b]Multi-Cpu Enhance[/b] (28 k): only a ProjectZomboid64.json: 8 GB heap, ParallelGC, NUMA, pre-touch. ParallelGC is a stop-the-world collector: a 300-350 ms full collection landed inside every route, where the game's own G1 never paused longer than 21 ms. Worse than stock.
[*][b]Every Texture Optimized[/b] (616 k): 6,142 re-encoded textures. Less VRAM, same frame time on a card that was not short of it.
[*][b]Lugli - Optimizations[/b] (3 k): ZombieBuddy patches: a wind gate that leaves calm vegetation in the chunk texture, a 19x19 instead of 361x361 z-extents scan, a room-square index. Needs calm wind and zoomed-out vegetation to have anything to gate; the routes had neither.
[*][b]Zed's Better FPS[/b] (47 k, with the community 42.20.2 fix): ZombieBuddy patches: GL state cache, sprite batching, ring buffer, DefaultShader, model MVP cache. All applied cleanly; nothing on the render thread's per-frame chunk / tree / translucent drawing or the game thread's world update, which are what set the frame time.
[*][b]This item[/b]: class overrides that move the chunk load, bake and lighting work off the game thread and cache what stock recomputes every frame. 481 / 246 / 456 fps on the same three routes, p99 8.8 / 13.8 / 8.5 ms.
[/list]
Not measured: BetterFPS_B42 (80 k, deprecated by its author, its page points to Zed's), HigherFPS (only removes the 244 fps cap; this item has the same option), Undying Optimizer (menus only), Horde Optimizer (hordes only). The Optimiser's author recommends not combining optimization mods; Lugli's page says the same. This item replaces whole classes; a ZombieBuddy mod that patches a method of one of them patches the replaced copy, so the two can load together (ZombieBuddy with Zed's loaded fine next to these files with the optimizations off), but both sets active together has not been measured and is not recommended. Full per-mod detail: docs/results.md in the repository, 2026-09-21.
