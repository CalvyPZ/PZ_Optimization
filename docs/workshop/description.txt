Single player and multiplayer, client side only. Steam version on Windows, Linux and macOS.

[h1]What it does[/h1]
Project Zomboid loads and bakes the map in chunks; on stock, the loading, baking and lighting work of a busy screen lands in the same frame and shows as stutter while driving or turning. These overrides move that work off the game thread, spread it over frames, and cache what stock recomputes every frame (puddles, rain, cutaways, light info, sound zones). At 5120x2160 on an RTX 4090: driving p99 frame time 19 -> 8 ms, uncapped ~270 -> ~500 fps, thunderstorms 83 -> 188 fps.

[h1]Boot and load times[/h1]
Launch to main menu and Continue to world ready, same save: stock 7.55 s + 7.67 s, optimized 4.88 s + 3.47 s. FMOD and the animation sets initialise on boot threads, Lua is precompiled and the animation clip and pack indexes are cached under Zomboid/pzopt/ (the first boot after installing is slower, every later one faster than stock).
[img]https://raw.githubusercontent.com/xD3I/PZ_Optimization/master/docs/workshop/images/01-boot-load.jpg[/img]

[h1]How it works[/h1]
The launcher (ProjectZomboid64.json) searches the game folder before projectzomboid.jar, so a loose .class file with the same name as one in the jar replaces it. The item holds those files (@NFILES@ entries: @NOVERRIDES@ shadowed game classes, the pzopt helper package, four Lua files, the preview clips and a manifest) under [b]pzopt-classes[/b]; projectzomboid.jar is never modified. A guard checks the game revision and the sha256 of every shadowed stock class at start-up; on any difference it logs one line and the game runs as stock.

[h1]Install on Windows[/h1]
1. Subscribe, let Steam download the item, close the game.
2. Open PowerShell (Start menu, type powershell) and run (adjust the drive if your Steam library is elsewhere):
[code]powershell -ExecutionPolicy Bypass -File "C:\Program Files (x86)\Steam\steamapps\workshop\content\108600\@ID@\mods\PZ_Optimization\42\install.ps1"[/code]
The script finds the game through Steam's library list, checks the revision, refuses to overwrite anything that already exists, copies the files next to the jar and records them in pzopt-installed.txt.
3. Launch from Steam. The first boot is a few seconds slower (caches under Zomboid\pzopt\); console.txt shows one "[pzopt] loaded override ... active" line per class.

Uninstall: the same command with -Uninstall. -Status lists what is installed and whether any file changed.

Without the script: copy the contents of the item's pzopt-classes folder next to projectzomboid.jar; removal is deleting the files listed in pzopt-files.txt.

[h1]Install on Linux and macOS[/h1]
Linux:
[code]bash ~/.local/share/Steam/steamapps/workshop/content/108600/@ID@/mods/PZ_Optimization/42/install.bash[/code]
macOS (Terminal; the files go into Project Zomboid.app/Contents/Java):
[code]bash ~/Library/Application\ Support/Steam/steamapps/workshop/content/108600/@ID@/mods/PZ_Optimization/42/install.bash[/code]
(Workshop items cannot contain .sh files, hence .bash.) Same flags: --status, --uninstall, --dir <game folder>.

[h1]Performance overlay (F9)[/h1]
Off by default: tick "Sample frame times and utilization" in Options > Optimizations > Performance overlay and restart, then F9 toggles it. Frame time and its tail (p99 / p99.9 / max, 1 %-low, jitter, spikes), GPU busy, game- and render-thread load, a verdict line, the game-thread tree and flame graph below, and the frame graph; every element is a dropdown there. Same numbers on every platform, no MangoHud or RivaTuner needed.
[img]https://raw.githubusercontent.com/xD3I/PZ_Optimization/master/docs/workshop/images/13-profiler.jpg[/img]

[h1]Settings[/h1]
Options > Optimizations (saved to Zomboid/pzopt/options.ini, applied on the next launch) has every key with a tick box, plus "Disable all (stock game)" / "Enable all". Options > Display gains an "Uncapped" framerate entry and a separate menu framerate.

[h1]Updates[/h1]
After the first install the menu item does the rest (one request to GitHub per boot; off in Options > Optimizations > Updates). The files are built for one game revision: after a game update the guard runs the game as stock (one console line) until the build for the new revision is out.

[h1]Compared with the other performance mods[/h1]
The most-subscribed Build 42 performance mods on the same three routes (120 km/h drive, the same drive in a thunderstorm, a spin through Rosewood), uncapped, one mod at a time. fps mean / p99 frame time:
[img]https://raw.githubusercontent.com/xD3I/PZ_Optimization/master/docs/workshop/images/10-workshop-mods-comparison.jpg[/img]
All of them measure within noise of stock: [b]Project Zomboid Optimiser[/b] flips engine debug toggles from Lua and swaps shaders for copies; [b]Tempo[/b] budgets chunk finalizing, not the chunk queue wait that is the tail; [b]Multi-Cpu Enhance[/b] is a launcher JSON whose ParallelGC adds a 300 ms pause per route (worse than stock); [b]Every Texture Optimized[/b] saves VRAM, not frame time; [b]Lugli[/b] and [b]Zed's Better FPS[/b] are ZombieBuddy patches that sit off the per-frame chunk, tree and translucent drawing. This item: 481 / 246 / 456 fps, p99 8.8 / 13.8 / 8.5 ms.
